# 开源音频播放器调研（音频解码学习参考）

> 用途：为从零搭建的 `AudioDecodeTestApp` 选择学习参考与技术路线。
> 调研时间：2026-11-17。信息来自公开仓库与官方文档，具体版本以各仓库为准。

## 1. 调研目标

本项目要做一个"测试各种编码格式音频文件"的 APK，本质是打通：

```
音频文件 → 解封装(容器) → 提取编码帧 → 解码(Codec) → PCM → 播放/校验
```

因此调研重点不是"哪个播放器 UI 好看"，而是**哪套源码能帮助理解解码链路**。

## 2. 核心播放器 / 解码库

### 2.1 AndroidX Media3（ExoPlayer）

- 仓库：<https://github.com/androidx/media>
- 定位：Google 官方 Jetpack 媒体库，ExoPlayer 的继任者，事实标准。
- 许可：Apache 2.0。

**架构链路（与音频解码直接相关）**：

```
MediaItem → MediaSource → MediaExtractor(解封装)
         → Renderer(渲染器) → MediaCodecAudioRenderer → MediaCodec → AudioSink(PCM 输出)
```

**为什么最适合本项目的学习**：
- 与你已学的 `MediaExtractor → MediaCodec → CCodec → Codec2 → C2SoftAacDec` 主线**完全对应**，能看到平台解码器如何被封装进完整播放管线。
- 自带 `extensions/ffmpeg` 模块，提供 `FfmpegAudioRenderer`，用 FFmpeg **软解** MediaCodec 不覆盖的格式（Vorbis、Opus、FLAC、AC-3、DTS、ALAC 等），是"多格式测试"的关键补充。

### 2.2 VLC / libVLC

- 仓库：<https://github.com/videolan/vlc-android>
- 定位：跨平台播放器，核心是 libVLC，插件化架构，几百个模块，格式覆盖最广。
- 许可：LGPL（GPL 部分需注意分发合规）。

**学习价值**：看 FFmpeg 软解 + 多容器/多协议如何在工程里组织；适合理解"全格式"能力从哪来。

### 2.3 FFmpeg

- 仓库：<https://github.com/FFmpeg/FFmpeg>
- 定位：底层编解码库，`libavcodec` 提供几乎所有格式的解码器。
- 许可：LGPL / GPL（可选组件不同）。

**学习价值**：纯软解底层，理解具体 codec 的 bitstream 解析与 PCM 输出（与你的 `C2SoftAacDec / FDK-AAC` 学习互补）。

### 2.4 平台 MediaCodec / NDK AMediaCodec

- 非开源但 AOSP 源码可查（CCodec / Codec2 / C2 组件），你已有 `docs/` 主线覆盖。
- 这是本项目默认使用的解码入口。

## 3. 上层音乐播放器（UI / 工程结构参考）

均为 2025-2026 年较活跃的项目，**解码能力都建立在 Media3/ExoPlayer 之上**，参考价值主要在 UI 与工程组织：

| 项目 | 技术栈 | 参考点 |
| --- | --- | --- |
| Levyra | Kotlin + Compose | 音质标识、多格式展示 |
| PixelPlayer | Kotlin + Compose + M3 | 离线本地播放、Material You |
| PixelMusic | Kotlin + Media3 | Hi-Res/FLAC、均衡器 |
| Audiofy | Media3 + Compose | 音视频统一、简洁架构 |
| android-music-player | Jetpack Media3 | 后台播放、MediaSessionService |
| Simple Player | Material 3 + Media3 | 极简 MVP，适合入门 |

## 4. 选型建议

1. **主线跟随 Media3（ExoPlayer）**：与既有 MediaCodec 学习路径一致，且是事实标准。
2. **格式覆盖扩展用 FFmpeg 软解**：需要时引入 `extensions/ffmpeg` 的 `FfmpegAudioRenderer`，覆盖 MediaCodec 缺失的格式。
3. **VLC 作为"全格式兜底"参考**：需要覆盖极端冷门格式时再考虑。
4. **本项目现阶段**：仅搭建界面框架，尚未接入音频选择与播放；后续按"MediaCodec 优先、FFmpeg 兜底"的顺序实现。

## 5. 与本项目的关系

- `AudioDecodeTestApp` 首期交付：Kotlin + Material 3 + AndroidX 的界面框架（底部导航 4 页）。
- 下一阶段再逐步接入：文件选择 → `MediaExtractor` 探针 → 解码 → PCM 校验。
